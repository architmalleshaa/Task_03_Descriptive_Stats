# From scripts to a reusable system

The statistical functions did not need dataset-specific changes when moving from ads to posts and tweets. The schema is discovered at runtime, input filenames and group keys are arguments, and identifier and type overrides are explicit. The same implementation was executed on all three full files and all three engines agreed. This is a direct generalization result, not a claim based on running three separately edited scripts.

The limits of generalization are semantic. A generic program can recognize 0/1 numeric values, but it cannot know whether a label is accurate, whether a blank video field means not applicable, or whether “interactions” and “likes” measure the same thing. The source's merged Facebook header exposed why automatically renaming columns until they match would be dangerous. It was preserved and documented as an unresolved source issue.

Grouping also needs domain judgment. The ad page keys were appropriate, and Facebook_Id supported 21 page groups. Twitter did not supply an account identifier. Month and posting source were selected as available, interpretable groupings, yielding 15 and 14 groups respectively. The program did not invent an account key or confuse a hashed post URL with a user identity.

Pure Python required the most explicit mechanics, but that made the handling of empty columns and singleton groups easy to inspect. Pandas and Polars reduced the aggregation code while still requiring careful control of nulls, types and output ordering. One end-to-end run on Facebook posts took about 0.64, 1.38 and 0.57 seconds respectively; Twitter took 0.97, 1.48 and 0.68 seconds. These are descriptive timings, not a robust speed ranking. Ads were slower because of their large nested strings and many output groups.

For another domain, such as a survey or transaction file, the core descriptive pass would run unchanged on a well-formed CSV that fits memory. The analyst would still need to choose meaningful group keys, review missing tokens, override identifiers that the name heuristic misses, check units and define any domain-specific derived metrics. Mixed types are deliberately preserved as categories until a justified cleaning rule is supplied; coercing every stray string to missing would be convenient but could bias results.

The common interface and output format made it possible to reuse the code across datasets. Validation was the necessary second step. The evidence here consists of known-answer edge cases and full-output comparisons, not an invented experiment with other coding assistants. Shared parsing means the engine comparison is not wholly independent, and the memory-resident implementation is not optimized for arbitrarily large sources. A future production version could separate streaming summaries from exact medians and high-cardinality frequency storage, but those are design proposals, not completed features.
